# 📖 Introduction

Linux ek hi file ke liye multiple file names allow karta hai.

In additional file names ko **Links** kaha jata hai.

Links ki wajah se ek hi file ya data ko multiple locations se access kiya ja sakta hai bina duplicate copy banaye.

Windows mein isi concept ko **Shortcut** kehte hain.

Lekin Linux mein Links do types ke hote hain:

1. **Hard Link**
2. **Soft Link (Symbolic Link)**

Har link type ke apne advantages, limitations aur use cases hote hain.

---

# Link Kya Hota Hai?

Ek **Link** sirf file ko access karne ka doosra tareeqa hota hai.

File ki duplicate copy banane ke bajaye Linux us file ka ek aur reference create karta hai.

Is se disk space bhi save hoti hai aur file management bhi efficient hoti hai.

---

# Windows Shortcut vs Linux Link

| Windows | Linux |
|----------|--------|
| Shortcut | Link |
| Shortcut (.lnk) file | Hard Link / Symbolic Link |
| Dusri file ko point karta hai | Original file ya uske inode ko point karta hai |

Windows Shortcut aur Linux Link dono file tak pohanchne ka alternate tareeqa dete hain, lekin Linux Links file system ke sath bohot zyada closely kaam karte hain.

---

# Links Ki Types

Linux do types ke Links support karta hai:

1. Hard Link
2. Symbolic Link (Soft Link)

---

# Soft Link (Symbolic Link) Kya Hota Hai?

Ek **Symbolic Link** ya **Soft Link** ek special file hoti hai jo kisi doosri file ko point karti hai.

Yeh actual data store nahi karti.

Balke yeh original file ka **path** store karti hai.

Isay aap ek signboard ki tarah samajh sakte hain jo Linux ko batata hai ke original file kahan maujood hai.

---

# Soft Link Ki Characteristics

Soft Link:

- Original file ko point karta hai.
- Original file ka path store karta hai.
- Apna alag inode number rakhta hai.
- Apni file permissions rakhta hai.
- Different file systems ke across create ho sakta hai.
- Directories ko bhi point kar sakta hai.
- Agar original file delete ho jaye to broken link ban jata hai.

---

# Soft Link Illustration

```text
Original File
     │
     ▼
report.txt
     ▲
     │
Soft Link
report-link.txt
```

Soft Link sirf original file ko point karta hai.

---

# Agar Original File Delete Ho Jaye To?

Suppose:

```text
Original File
```

delete ho gayi.

Soft Link phir bhi exist karega.

Lekin ab woh aisi file ko point karega jo ab maujood hi nahi.

Example:

```text
Original File      ❌ Deleted

Soft Link
      │
      ▼
Broken Link
```

Soft Link ab **Broken Link** ban gaya hai kyun ke uska target ab exist nahi karta.

---

# Hard Link Kya Hota Hai?

Ek **Hard Link** original file ka doosra directory entry hota hai jo directly usi inode ko point karta hai.

Yeh file path ko point nahi karta.

Balke original file ke **same inode** ko point karta hai.

Original file aur Hard Link dono ek hi data ko access karte hain.

---

# Hard Link Illustration

```text
Original File
      │
      ▼
      Inode
        │
   ┌────┴────┐
   │         │
Original   Hard Link
Filename   Filename
```

Dono file names same inode aur same data ko point karte hain.

---

# Hard Link Ki Characteristics

Hard Link:

- Same inode share karta hai.
- Same data share karta hai.
- Same permissions share karta hai.
- Same ownership share karta hai.
- Different file systems ke across create nahi ho sakta.
- Directories ke liye create nahi kiya ja sakta.
- Original filename delete hone ke baad bhi data available rehta hai.

---

# Agar Original File Delete Ho Jaye To?

Suppose:

```text
Original File
```

delete kar di gayi.

Hard Link phir bhi usi inode ko point karega.

Example:

```text
Original File     ❌ Deleted

Hard Link
      │
      ▼
Same Inode
      │
      ▼
Data Still Exists
```

Hard Link ke through file bilkul accessible rehti hai.

Data tab tak delete nahi hota jab tak us inode ke tamam Hard Links remove na kar diye jayein.

---

# Soft Link vs Hard Link

| Feature | Soft Link | Hard Link |
|----------|-----------|-----------|
| Kis ko point karta hai | File Path | Inode |
| Actual data store karta hai | No | No |
| Same inode share karta hai | No | Yes |
| Different file systems cross kar sakta hai | Yes | No |
| Directories ko point kar sakta hai | Yes | No |
| Original delete hone par broken ho jata hai | Yes | No |
| Same permissions | No | Yes |
| Same ownership | No | Yes |

---

# Inode Numbers

Hard Link aur Soft Link ka sab se bara difference inode numbers se samjha ja sakta hai.

### Soft Link

```text
Original File
Inode = 12345

Soft Link
Inode = 98765
```

Dono ke inode numbers alag hote hain.

---

### Hard Link

```text
Original File
Inode = 12345

Hard Link
Inode = 12345
```

Dono ka inode number same hota hai.

---

# File Permissions

## Soft Link

Soft Link ka apna inode hota hai.

Is liye:

- Apni file permissions hoti hain.
- Original file ki permissions change karne se Soft Link ka inode change nahi hota.

Lekin jab file access hoti hai to Linux original target file ki permissions use karta hai.

---

## Hard Link

Hard Link same inode use karta hai.

Is liye:

- Same inode
- Same owner
- Same group
- Same permissions

Agar original file ki permissions change karein to Hard Link par bhi wohi changes nazar aayengi.

---

# File System Limitations

Suppose aap ke paas do alag file systems hain:

```text
/db

/oradb
```

Har mounted file system ka apna inode table hota hai.

---

## Soft Link

Soft Link sirf path store karta hai.

Is liye yeh kisi bhi file system ko point kar sakta hai.

Example:

```text
/db/report.txt
        │
        ▼
Soft Link
        │
        ▼
/oradb/report-link.txt
```

Yeh allowed hai.

---

## Hard Link

Hard Link same inode ko point karta hai.

Kyun ke inode sirf ek hi file system ke andar valid hota hai, is liye Hard Link doosre file system mein create nahi ho sakta.

Example:

```text
/db/report.txt
        │
        ▼
Hard Link
        │
        ▼
/oradb/report-link.txt
```

Yeh allowed nahi hai.

---

# Directory Limitation

Soft Links:

✅ Directories ko point kar sakte hain.

Hard Links:

❌ Normally directories ke liye create nahi kiye ja sakte.

Is restriction ki wajah file system ko directory loops se bachana hota hai.

---

# Real-World Example

Suppose aap ke paas:

```text
/home/student/report.txt
```

Aur aap ek aur convenient path banana chahte hain:

```text
/projects/current-report.txt
```

### Agar Soft Link banayenge:

Nayi file sirf original file ka path point karegi.

Original file delete ho gayi to Soft Link bhi kaam nahi karega.

---

### Agar Hard Link banayenge:

Naya filename same inode ko point karega.

Original filename delete hone ke baad bhi data available rahega.

---

# Soft Link Ke Advantages

- Different file systems ke across create ho sakta hai.
- Directories ko point kar sakta hai.
- Flexible hai.
- Manage karna asaan hai.
- Shortcuts ki tarah use hota hai.

---

# Hard Link Ke Advantages

- Original filename delete hone ke baad bhi data available rehta hai.
- Duplicate data create nahi hota.
- Same inode use karta hai.
- Disk space efficient hoti hai.
- Kisi bhi filename se ki gayi changes foran doosre naam par bhi nazar aati hain.

---

# Soft Link Ke Disadvantages

- Original file delete hone par broken ho jata hai.
- Alag inode hota hai.
- Original file ke path par depend karta hai.

---

# Hard Link Ke Disadvantages

- Different file systems cross nahi kar sakta.
- Directories ke liye create nahi kiya ja sakta.
- Multiple names ki wajah se file management kabhi kabhi confusing ho sakti hai.

---

# 📌 Quick Revision

| Concept | Description |
|----------|-------------|
| Link | File ka doosra naam ya reference |
| Hard Link | Original file ke same inode ko share karta hai |
| Soft Link | Original file ka path store karta hai |
| Inode | File ka metadata identifier |
| Broken Link | Soft Link jiska target exist nahi karta |
| File System Boundary | Hard Link cross nahi kar sakta |

---

# 📖 Key Takeaways

- Linux do types ke Links support karta hai: Hard Link aur Soft Link.
- Soft Link file ka path store karta hai.
- Hard Link directly same inode ko point karta hai.
- Hard Link original filename delete hone ke baad bhi kaam karta hai.
- Soft Link original file delete hone par broken ho jata hai.
- Soft Link different file systems ke across create ho sakta hai.
- Hard Link different file systems ke across create nahi ho sakta.
- Soft Link directories ko point kar sakta hai.
- Hard Link normally directories ke liye create nahi kiya jata.
- Hard Link aur original file same inode aur metadata share karte hain.

---

# 💡 Yaad Rakhein

> **Soft Link ko ghar ke address ki tarah aur Hard Link ko usi ghar ke doosre official naam ki tarah samjhein.**
>
> - **Soft Link** sirf address batata hai. Agar ghar gira diya jaye ya move ho jaye to address bekaar ho jata hai.
> - **Hard Link** usi ghar ka doosra official naam hota hai. Agar ek naam hata diya jaye to bhi ghar doosre naam se maujood rehta hai.
>
> **Golden Rule:**
>
> ```text
> Soft Link
>     │
>     ▼
> File Path Ko Point Karta Hai
>
> Hard Link
>     │
>     ▼
> Same Inode Ko Point Karta Hai
> ```
