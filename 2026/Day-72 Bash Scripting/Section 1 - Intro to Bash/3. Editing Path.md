# MODULE 12 – Editing the `PATH` Environment Variable
> **Running Bash Scripts Without Using `./` or the Full File Path**

---

# 🎯 Learning Objectives

By the end of this lesson, you will be able to:

- Understand what the `PATH` environment variable is.
- Understand how the shell searches for commands.
- Display the current value of the `PATH` variable.
- Recognize the colon (`:`) as the directory separator inside `PATH`.
- Add your scripts directory to `PATH`.
- Run Bash scripts without using `./`.
- Understand the difference between a temporary and permanent `PATH` change.

---

# 📖 Introduction

In the previous lesson, we created an executable Bash script named:

```text
hello.sh
```

We were able to run it using:

```bash
./hello.sh
```

or by providing its complete path:

```bash
/home/elliot/scripts/hello.sh
```

Although both methods work, they are not always convenient.

In this lesson, we will add the scripts directory to the `PATH` environment variable.

After updating `PATH`, we will be able to run the script simply by typing:

```bash
hello.sh
```

---

# What Is the `PATH` Environment Variable?

The `PATH` variable contains a list of directories where the shell searches for executable commands.

When you type:

```bash
ls
```

you do not normally need to type:

```bash
/bin/ls
```

This is because the directory containing the `ls` command is already included in `PATH`.

The shell automatically searches the directories listed in `PATH` until it finds an executable file with the requested name.

---

# Command Search Flow

```text
User Types a Command
        │
        ▼
Shell Reads the PATH Variable
        │
        ▼
Searches Each Directory in Order
        │
        ├── Directory 1
        ├── Directory 2
        ├── Directory 3
        └── Directory 4
        │
        ▼
Executable Found
        │
        ▼
Command Runs
```

If the shell cannot find the command in any directory listed in `PATH`, it displays:

```text
command not found
```

---

# Why Does `hello.sh` Fail?

Suppose you are inside:

```text
/home/elliot/scripts
```

and run:

```bash
hello.sh
```

You may receive:

```text
hello.sh: command not found
```

The file exists, but the current directory is not normally included in the `PATH` variable.

Therefore, the shell does not automatically search the current directory.

---

# Ways to Run the Script Before Editing `PATH`

You can run the script by referencing the current directory:

```bash
./hello.sh
```

You can also use the complete path:

```bash
/home/elliot/scripts/hello.sh
```

Both commands tell the shell exactly where the script is located.

---

# Why Use `./`?

The dot (`.`) represents the current directory.

Therefore:

```bash
./hello.sh
```

means:

> Run `hello.sh` from the current directory.

---

# Display the Current `PATH`

Use the following command:

```bash
echo $PATH
```

Example Output:

```text
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin
```

---

# Understanding the `PATH` Output

The colon character:

```text
:
```

separates one directory from another.

For example:

```text
/usr/local/sbin
```

is the first directory.

```text
/usr/local/bin
```

is the second directory.

```text
/usr/sbin
```

is the third directory.

The shell searches these directories from left to right.

---

# Example `PATH` Structure

```text
/usr/local/sbin
        │
        ▼
/usr/local/bin
        │
        ▼
/usr/sbin
        │
        ▼
/usr/bin
        │
        ▼
/sbin
        │
        ▼
/bin
```

The first matching executable found is the one that runs.

---

# Verify the Scripts Directory

Suppose your scripts are stored in:

```text
/home/elliot/scripts
```

Verify that the directory exists:

```bash
ls -ld /home/elliot/scripts
```

Verify the script:

```bash
ls -l /home/elliot/scripts/hello.sh
```

The script must have execute permission.

Example:

```text
-rwxr--r-- 1 elliot elliot 38 Jul 14 10:00 hello.sh
```

---

# Add the Scripts Directory to `PATH`

Use the `export` command:

```bash
export PATH=$PATH:/home/elliot/scripts
```

---

# Understanding the Command

| Part | Description |
|------|-------------|
| `export` | Makes the variable available to the current shell and its child processes |
| `PATH=` | Assigns a new value to the `PATH` variable |
| `$PATH` | Preserves all directories already in `PATH` |
| `:` | Separates directory entries |
| `/home/elliot/scripts` | Adds the scripts directory |

---

# Why Include `$PATH`?

The following command is correct:

```bash
export PATH=$PATH:/home/elliot/scripts
```

It preserves the existing directories and adds the new directory.

If you run:

```bash
export PATH=/home/elliot/scripts
```

you replace the entire existing `PATH`.

This can prevent normal commands such as `ls`, `cat`, and `grep` from working by name.

---

# PATH Before the Change

```text
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

---

# PATH After the Change

```text
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/home/elliot/scripts
```

The scripts directory has been appended to the end.

---

# Verify the Updated `PATH`

Run:

```bash
echo $PATH
```

You should now see:

```text
/home/elliot/scripts
```

inside the output.

For easier viewing, you can display each directory on a separate line:

```bash
echo "$PATH" | tr ':' '\n'
```

Example Output:

```text
/usr/local/sbin
/usr/local/bin
/usr/sbin
/usr/bin
/sbin
/bin
/home/elliot/scripts
```

---

# Run the Script Without `./`

Now execute:

```bash
hello.sh
```

Expected Output:

```text
Hello Friend
```

You no longer need to use:

```bash
./hello.sh
```

or:

```bash
/home/elliot/scripts/hello.sh
```

The shell finds the script by searching the directories listed in `PATH`.

---

# Script Search Flow

```text
User Types hello.sh
        │
        ▼
Shell Reads PATH
        │
        ▼
Searches PATH Directories
        │
        ▼
Finds /home/elliot/scripts/hello.sh
        │
        ▼
Reads the Shebang
        │
        ▼
Starts /bin/bash
        │
        ▼
Script Executes
```

---

# Confirm Which File Will Run

Use:

```bash
which hello.sh
```

Expected Output:

```text
/home/elliot/scripts/hello.sh
```

You can also use:

```bash
command -v hello.sh
```

Expected Output:

```text
/home/elliot/scripts/hello.sh
```

`command -v` is generally more reliable in shell scripts.

---

# Temporary `PATH` Change

The command:

```bash
export PATH=$PATH:/home/elliot/scripts
```

changes `PATH` only for the current shell session.

If you:

- Log out
- Close the terminal
- Open a new shell session

the change may disappear.

This is known as a **temporary PATH change**.

---

# Make the `PATH` Change Permanent

For Bash users, add the export command to:

```text
~/.bashrc
```

Run:

```bash
echo 'export PATH="$PATH:$HOME/scripts"' >> ~/.bashrc
```

Then reload the file:

```bash
source ~/.bashrc
```

or:

```bash
. ~/.bashrc
```

Verify:

```bash
echo "$PATH" | tr ':' '\n'
```

---

# Why Use `$HOME`?

Instead of writing:

```bash
/home/elliot/scripts
```

you can write:

```bash
$HOME/scripts
```

The `$HOME` variable automatically represents the current user's home directory.

Example:

```bash
echo $HOME
```

Output:

```text
/home/elliot
```

Therefore:

```text
$HOME/scripts
```

becomes:

```text
/home/elliot/scripts
```

---

# Recommended Permanent Configuration

Add the following line to `~/.bashrc`:

```bash
export PATH="$PATH:$HOME/scripts"
```

This is more portable than hard-coding a username.

---

# View the `.bashrc` Entry

Run:

```bash
tail -n 5 ~/.bashrc
```

You should see:

```bash
export PATH="$PATH:$HOME/scripts"
```

---

# Test from Another Directory

Move outside the scripts directory:

```bash
cd /tmp
```

Run:

```bash
hello.sh
```

Expected Output:

```text
Hello Friend
```

This proves that the shell can find the script regardless of your current directory.

---

# Duplicate `PATH` Entries

If you repeatedly run:

```bash
export PATH=$PATH:$HOME/scripts
```

the same directory may appear multiple times.

Check:

```bash
echo "$PATH" | tr ':' '\n'
```

Repeated entries normally do not stop commands from working, but they make the configuration untidy.

Add the export command only once to your shell configuration file.

---

# Directory Order Matters

The shell searches `PATH` from left to right.

Suppose two commands have the same name:

```text
/usr/bin/backup
```

and:

```text
/home/elliot/scripts/backup
```

Whichever directory appears first in `PATH` determines which command runs.

---

# Security Consideration

Avoid adding the current directory using:

```bash
export PATH=.:$PATH
```

This can be dangerous because a malicious executable in the current directory could run instead of a trusted system command.

It is safer to add a specific scripts directory:

```bash
export PATH="$PATH:$HOME/scripts"
```

# 🔧 Troubleshooting

## Problem 1 – `hello.sh: command not found`

Check whether the scripts directory exists in `PATH`:

```bash
echo "$PATH" | tr ':' '\n'
```

If it is missing:

```bash
export PATH="$PATH:$HOME/scripts"
```

---

## Problem 2 – `Permission denied`

Verify permissions:

```bash
ls -l "$HOME/scripts/hello.sh"
```

Add execute permission:

```bash
chmod u+x "$HOME/scripts/hello.sh"
```

---

## Problem 3 – `which hello.sh` Shows Nothing

Check:

- The file exists.
- The file is executable.
- The containing directory is in `PATH`.

Run:

```bash
ls -l "$HOME/scripts/hello.sh"
```

```bash
echo "$PATH" | tr ':' '\n'
```

---

## Problem 4 – PATH Change Disappears After Logout

The change was temporary.

Add it to:

```text
~/.bashrc
```

Then reload:

```bash
source ~/.bashrc
```

---

## Problem 5 – Normal Commands Stop Working

You may have replaced `PATH` instead of appending to it.

Incorrect:

```bash
export PATH="$HOME/scripts"
```

Correct:

```bash
export PATH="$PATH:$HOME/scripts"
```

To restore a basic temporary `PATH`, run:

```bash
export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

Then fix the configuration file.

# 📖 Key Takeaways

- `PATH` is a list of directories where the shell searches for commands.
- Directory entries inside `PATH` are separated by colons (`:`).
- The shell searches `PATH` from left to right.
- Adding the scripts directory allows scripts to run without `./`.
- Always preserve the existing `PATH` by including `$PATH`.
- `export PATH="$PATH:$HOME/scripts"` makes a temporary change.
- Add the command to `~/.bashrc` to make it persistent.
- The script must still have execute permission.
- Avoid adding the current directory to `PATH` for security reasons.

---

# 💡 Remember

> **Think of `PATH` as the shell's directory address book.**
>
> - When you type a command, the shell checks every address listed in `PATH`.
> - If it finds the executable, it runs it.
> - If the directory is not listed, the shell cannot find the command unless you provide its location.
>
> **Golden Rule:**
>
> ```text
> User Types Command
>         │
>         ▼
> Shell Searches PATH
>         │
>         ▼
> Executable Found
>         │
>         ▼
> Command Runs
> ```
>
> Add your scripts directory to `PATH` when you want your Bash scripts to behave like normal Linux commands.
