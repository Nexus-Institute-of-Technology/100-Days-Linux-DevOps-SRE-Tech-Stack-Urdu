# What is a Shebang?

The first line of every Bash script usually contains:

```bash
#!/bin/bash
```

This line is called the **Shebang**.

The word **Shebang** comes from:

```text
#
```

called:

```text
Hash
```

followed by:

```text
!
```

called:

```text
Bang
```

Together:

```text
Hash + Bang = Shebang
```

---

# Why is it Called "Shebang"?

In the Linux community:

```text
#
```

is called:

```text
Hash
```

and

```text
!
```

is commonly called:

```text
Bang
```

Putting them together gives:

```text
Hash Bang
```

which became shortened to:

```text
Shebang
```

Whenever someone refers to the **Shebang**, they mean:

```bash
#! 
```

at the beginning of a script.

---

# Why Do We Need the Shebang?

The Shebang tells Linux:

> **Which interpreter should execute this script.**

For a Bash script:

```bash
#!/bin/bash
```

Linux understands that the Bash shell should interpret every command inside the file.

Without the Shebang, Linux may not know which interpreter should execute the script.

---

# Script Structure

Our completed script now looks like this:

```bash
#!/bin/bash

echo "Hello Friend"
```

Notice that the Shebang must always be the **first line** of the file.

---

# Why Must It Be the First Line?

Linux checks the first line of an executable script.

If it sees:

```bash
#!/bin/bash
```

it immediately launches:

```text
/bin/bash
```

and passes the script to Bash for execution.

---

# Editing the Script

Open the script:

```bash
vim hello.sh
```

or

```bash
nano hello.sh
```

Add the first line:

```bash
#!/bin/bash
```

Your file should now contain:

```bash
#!/bin/bash

echo "Hello Friend"
```

Save the file.

---

# Viewing the Script

Verify:

```bash
cat hello.sh
```

Expected Output:

```bash
#!/bin/bash

echo "Hello Friend"
```

---

# Why Doesn't the Script Run Yet?

Suppose you try:

```bash
./hello.sh
```

Linux responds:

```text
Permission denied
```

Why?

Because the file is **not executable**.

At this point, it is still just a normal text file.

---

# File Permissions

Check the permissions:

```bash
ls -l
```

Example:

```text
-rw-r--r-- hello.sh
```

Notice there is **no execute permission** (`x`).

---

# Making the Script Executable

Use the `chmod` command.

To give execute permission to the owner:

```bash
chmod u+x hello.sh
```

Where:

- `u` = User (Owner)
- `+` = Add Permission
- `x` = Execute Permission

---

# Alternative

To make the script executable for everyone:

```bash
chmod +x hello.sh
```

This grants execute permission to:

- Owner
- Group
- Others

---

# Verify Permissions

Run:

```bash
ls -l
```

Example Output:

```text
-rwxr--r-- hello.sh
```

Notice the:

```text
x
```

The file is now executable.

---

# Running the Script

Execute:

```bash
./hello.sh
```

Output:

```text
Hello Friend
```

Linux performs the following steps:

1. Finds the file.
2. Reads the Shebang.
3. Starts `/bin/bash`.
4. Bash executes the script.
5. The output is displayed.

---

# Execution Flow

```text
User Runs Script
        │
        ▼
./hello.sh
        │
        ▼
Linux Reads First Line
        │
        ▼
#!/bin/bash
        │
        ▼
Starts Bash
        │
        ▼
Bash Executes Commands
        │
        ▼
Hello Friend
```

# Why Do We Use `./`?

The command:

```bash
./hello.sh
```

means:

```text
Run hello.sh from the current directory.
```

Here:

```text
.
```

represents:

```text
Current Directory
```

Example:

```bash
pwd
```

Output:

```text
/home/elliot/scripts
```

Then:

```bash
./hello.sh
```

means:

```text
Run:

/home/elliot/scripts/hello.sh
```

---

# Current Directory vs Parent Directory

Linux shortcuts:

```text
.
```

Current Directory

```text
..
```

Parent Directory

Example:

```bash
pwd
```

```text
/home/elliot/scripts
```

Then:

```bash
cd ..
```

takes you to:

```text
/home/elliot
```

---

# Why Doesn't This Work?

Suppose you type:

```bash
hello.sh
```

Linux responds:

```text
Command not found
```

Why?

Because Linux searches only the directories listed in the **PATH** environment variable.

The current directory is usually **not included** in PATH.

Therefore, Linux cannot find:

```text
hello.sh
```

unless you specify:

```bash
./hello.sh
```

# 📌 Quick Revision

| Command | Purpose |
|----------|---------|
| `#!/bin/bash` | Bash interpreter declaration (Shebang) |
| `chmod u+x hello.sh` | Give execute permission to owner |
| `chmod +x hello.sh` | Give execute permission to everyone |
| `ls -l` | View file permissions |
| `./hello.sh` | Execute script from current directory |
| `cat hello.sh` | Display script contents |

---

# 📖 Key Takeaways

- A Bash script should begin with the **Shebang** line.
- The Shebang tells Linux which interpreter to use.
- The Shebang must always be the first line.
- Scripts must have execute permission before they can be run directly.
- `chmod` is used to add execute permissions.
- `./` tells Linux to execute the script from the current directory.
- Simply typing the script name usually fails because the current directory is not part of the PATH variable.

---

# 💡 Remember

> **Think of the Shebang as the address written on an envelope.**
>
> - The operating system receives the script.
> - It first checks the address (`#!/bin/bash`).
> - It knows exactly where to deliver the script.
> - Bash receives the script and executes every command inside it.
>
> **Golden Rule:**
>
> ```text
> Script
>    │
>    ▼
> Shebang
>    │
>    ▼
> Bash Interpreter
>    │
>    ▼
> Commands Execute
>    │
>    ▼
> Output
> ```
>
> **Every professional Bash script should begin with a Shebang and should have execute permission before it is run directly.**
