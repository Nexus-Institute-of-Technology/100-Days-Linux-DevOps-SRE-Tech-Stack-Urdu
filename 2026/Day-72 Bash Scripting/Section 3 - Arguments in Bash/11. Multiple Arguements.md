# What Are Multiple Arguments?

Multiple arguments are several values supplied after the script name.

Example:

```bash
./count-lines.sh /etc/passwd /etc/group /etc/hosts
```

The arguments are assigned by position.

```text
$0 = ./count-lines.sh
$1 = /etc/passwd
$2 = /etc/group
$3 = /etc/hosts
```

---

# Argument Position Diagram

```text
./count-lines.sh /etc/passwd /etc/group /etc/hosts
        │              │            │          │
        │              │            │          └── $3
        │              │            └───────────── $2
        │              └────────────────────────── $1
        └───────────────────────────────────────── $0
```

---

# Positional Parameters

| Parameter | Meaning |
|---|---|
| `$0` | Script name |
| `$1` | First argument |
| `$2` | Second argument |
| `$3` | Third argument |
| `$4` | Fourth argument |
| `$5` | Fifth argument |

The numbering continues as more arguments are passed.

# What Happens If an Argument Is Missing?

Run the three-file script with only two arguments:

```bash
./count-three-files.sh /etc/passwd /etc/group
```

The script expects:

```bash
$3
```

but no third argument was provided.

You may see an error similar to:

```text
ambiguous redirect
```

or:

```text
No such file or directory
```

The exact message depends on the shell and the command used.

---

# Why Does the Error Occur?

This line:

```bash
LINES_THREE=$(wc -l < "$3")
```

expects `$3` to contain a filename.

If `$3` is empty, Bash cannot correctly redirect input from the missing path.

```text
Expected:
wc -l < "/etc/hosts"

Received:
wc -l < ""
```

# Understanding the Validation

```bash
if [ "$#" -ne 3 ]; then
```

This means:

> If the number of arguments is not equal to three, display an error.

| Part | Meaning |
|---|---|
| `$#` | Number of arguments |
| `-ne` | Not equal |
| `3` | Required number |

# LAB 8 – Validate All Three Files

Use the following complete script:

```bash
#!/bin/bash

# Script Name: count-three-files.sh
# Purpose: Count lines in three files supplied as arguments.

if [ "$#" -ne 3 ]; then
    echo "Error: Exactly three files are required."
    echo "Usage: $0 FILE1 FILE2 FILE3"
    exit 1
fi

FILE_ONE="$1"
FILE_TWO="$2"
FILE_THREE="$3"

if [ ! -f "$FILE_ONE" ]; then
    echo "Error: '$FILE_ONE' is not a regular file."
    exit 2
fi

if [ ! -f "$FILE_TWO" ]; then
    echo "Error: '$FILE_TWO' is not a regular file."
    exit 3
fi

if [ ! -f "$FILE_THREE" ]; then
    echo "Error: '$FILE_THREE' is not a regular file."
    exit 4
fi

LINES_ONE=$(wc -l < "$FILE_ONE")
LINES_TWO=$(wc -l < "$FILE_TWO")
LINES_THREE=$(wc -l < "$FILE_THREE")

echo "========================================"
echo "          THREE-FILE LINE REPORT"
echo "========================================"
echo "$FILE_ONE: $LINES_ONE lines"
echo "$FILE_TWO: $LINES_TWO lines"
echo "$FILE_THREE: $LINES_THREE lines"
echo "========================================"
```

# 🔧 Troubleshooting

## Problem 1 – Ambiguous Redirect

Possible command:

```bash
./count-three-files.sh /etc/passwd /etc/group
```

Cause:

The script expects `$3`, but no third argument was provided.

Solution:

```bash
if [ "$#" -ne 3 ]; then
    echo "Usage: $0 FILE1 FILE2 FILE3"
    exit 1
fi
```

---

## Problem 2 – Arguments Appear in the Wrong Position

Example:

```bash
./student-info.sh IT Ahmed Houston
```

The script will assign:

```text
$1 = IT
$2 = Ahmed
$3 = Houston
```

Arguments must be passed in the order expected by the script.

---

## Problem 3 – Value with Spaces Becomes Multiple Arguments

Incorrect:

```bash
./student-info.sh Ahmed Khan Linux Administration
```

Correct:

```bash
./student-info.sh Ahmed Khan "Linux Administration"
```

---

if [ ! -f "$1" ]; then

# 📌 Quick Revision

| Syntax | Purpose |
|---|---|
| `$0` | Script name |
| `$1` | First argument |
| `$2` | Second argument |
| `$3` | Third argument |
| `$#` | Number of arguments |
| `"$1"` | Safely reference the first argument |
| `[ "$#" -ne 3 ]` | Check that exactly three arguments were supplied |
| `wc -l < "$1"` | Count lines in the first file |
| `$((A + B + C))` | Add integer values |
| `exit 1` | Stop the script with an error status |

# 📖 Key Takeaways

- Multiple arguments are passed after the script name.
- `$1`, `$2`, and `$3` represent arguments by position.
- The order of arguments matters.
- `$#` tells you how many arguments were supplied.
- Missing arguments can cause redirect and file errors.
- Scripts should validate the expected number of arguments.
- File arguments should be checked before use.
- Values containing spaces must be quoted.
- Named variables make positional arguments easier to understand.
- Command substitution can process each argument separately.

---

# 💡 Remember

> **Each argument has a numbered position.**

```text
./script.sh first second third
              │      │      │
              ▼      ▼      ▼
             $1     $2     $3
```

## Golden Rule

Validate the number of arguments before using them:

```bash
if [ "$#" -ne 3 ]; then
    echo "Usage: $0 ARGUMENT1 ARGUMENT2 ARGUMENT3"
    exit 1
fi
```

Then assign them to meaningful variables:

```bash
FIRST_ARGUMENT="$1"
SECOND_ARGUMENT="$2"
THIRD_ARGUMENT="$3"
```

This makes Bash scripts safer, clearer, and easier to maintain.
