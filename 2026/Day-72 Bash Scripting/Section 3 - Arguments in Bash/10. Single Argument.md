# What Is a Bash Argument?

A Bash argument is a value supplied to a script when the script is executed.

Example:

```bash
./count-lines.sh /etc/passwd
```

In this command:

```text
./count-lines.sh
```

is the script.

```text
/etc/passwd
```

is the first argument passed to the script.

Inside the script, the first argument is represented by:

```bash
$1
```

---

# Argument Position Diagram

```text
./count-lines.sh /etc/passwd
        │              │
        │              └── First argument: $1
        │
        └── Script name: $0
```

# Why Use Arguments?

Arguments make scripts:

- Faster to use
- Easier to automate
- Easier to reuse
- Better suited for cron jobs
- Better suited for DevOps pipelines
- Less dependent on interactive input

Instead of asking the user:

```text
Please enter a filename:
```

the user provides the filename directly:

```bash
./count-lines.sh /etc/passwd
```


## Prompt the User

```bash

```

This asks the user to type a file path.

---

## Read the Input

```bash

```

The user's input is stored in the variable:

```bash
FILE_NAME
```

---

## Count the Lines

```bash
NUMBER_OF_LINES=$(wc -l < "$FILE_NAME")
```

This uses command substitution.

The command:

```bash
wc -l
```

counts lines.

The input redirection:

```bash
< "$FILE_NAME"
```

sends the file into `wc -l`.

The result is stored in:

```bash
NUMBER_OF_LINES
```

---

## Display the Result

```bash
echo "There are $NUMBER_OF_LINES lines in $FILE_NAME."
```

---

# Why Use Input Redirection?

The following command:

```bash
wc -l /etc/passwd
```

usually displays:

```text
35 /etc/passwd
```

But:

```bash
wc -l < /etc/passwd
```

displays only:

```text
35
```

This makes the output easier to store in a variable.

# What Does `$1` Mean?

```bash
$1
```

means:

> The first argument passed to the script.

Example:

```bash
./count-lines.sh /etc/passwd
```

Bash interprets this as:

```text
$0 = ./count-lines.sh
$1 = /etc/passwd
```

---

# Positional Parameters

Arguments are stored in positional parameters.

| Parameter | Meaning |
|---|---|
| `$0` | Script name |
| `$1` | First argument |
| `$2` | Second argument |
| `$3` | Third argument |
| `$4` | Fourth argument |

In this lesson, only `$1` is required.

---

# Argument Processing Flow

```text
User Runs Script
       │
       ▼
./count-lines.sh /etc/passwd
       │
       ▼
Bash Assigns /etc/passwd to $1
       │
       ▼
wc -l Reads the File
       │
       ▼
Line Count Is Stored
       │
       ▼
Result Is Displayed
```

# Why Assign `$1` to a Variable?

This:

```bash
FILE_PATH="$1"
```

makes the script easier to read.

Compare:

```bash
NUMBER_OF_LINES=$(wc -l < "$1")
```

with:

```bash
FILE_PATH="$1"

NUMBER_OF_LINES=$(wc -l < "$FILE_PATH")
```

Both work, but the second form is clearer in longer scripts.

# Interactive Input vs Arguments

| Interactive Input | Command-Line Argument |
|---|---|
| Uses `read` | Uses `$1` |
| User is prompted | Value is passed when executed |
| Better for guided input | Better for automation |
| Requires interaction | Can run unattended |
| Harder to use in cron | Ideal for cron and pipelines |

# Suggested File Report Script

```bash
#!/bin/bash

FILE_PATH="$1"

if [ -z "$FILE_PATH" ]; then
    echo "Usage: $0 FILE"
    exit 1
fi

if [ ! -f "$FILE_PATH" ]; then
    echo "Error: '$FILE_PATH' is not a regular file."
    exit 2
fi

LINES=$(wc -l < "$FILE_PATH")
WORDS=$(wc -w < "$FILE_PATH")
CHARACTERS=$(wc -m < "$FILE_PATH")
SIZE=$(du -h "$FILE_PATH" | awk '{print $1}')
OWNER=$(stat -c '%U' "$FILE_PATH")
PERMISSIONS=$(stat -c '%A' "$FILE_PATH")

echo "=================================="
echo "          FILE REPORT"
echo "=================================="
echo "File:        $FILE_PATH"
echo "Lines:       $LINES"
echo "Words:       $WORDS"
echo "Characters:  $CHARACTERS"
echo "Size:        $SIZE"
echo "Owner:       $OWNER"
echo "Permissions: $PERMISSIONS"
echo "=================================="
```

# 🔧 Troubleshooting

## Problem 1 – No Argument Supplied


## Problem 2 – File Does Not Exist

Command:

```bash

```

Solution:

```bash
if [ ! -f "$1" ]; then
    echo "Error: File not found."
    exit 2
fi
```

## Problem 3 – Filename Contains Spaces

Suppose the file is:

```text
student notes.txt
```

Run:

```bash
./count-lines.sh "student notes.txt"
```

Inside the script, always use:

```bash
"$1"
```

not:

```bash

```

---

## Problem 4 – Permission Denied

Make the script executable:

```bash
chmod u+x count-lines.sh
```

Then run:

```bash

```

---

## Problem 5 – Script Not Found Through `PATH`

The easiest beginner method is:

```bash
./count-lines.sh /etc/passwd
```

To run it from anywhere, add the scripts directory to `PATH`:

```bash
export PATH="$PATH:$HOME/scripts"
```

Then run:

```bash
count-lines.sh /etc/passwd
```

To make the change persistent:

```bash
echo 'export PATH="$PATH:$HOME/scripts"' >> ~/.bashrc
```

Reload:

```bash
source ~/.bashrc
```

---

## Problem 6 – Wrong Output from `wc -l`

This:

```bash
wc -l "$1"
```

returns both the count and filename.

Use:

```bash
wc -l < "$1"
```

to return only the number.

# 📖 Key Takeaways

- Arguments are passed to a script when the script is executed.
- `$1` represents the first argument.
- `$0` represents the script name.
- Arguments can replace interactive `read` commands.
- Argument-based scripts are easier to automate.
- File paths should be quoted.
- Scripts should validate that an argument was supplied.
- Scripts should confirm that a requested file exists.
- Command substitution can process the argument and store the result.

## Golden Rule

```bash
VARIABLE="$1"
```

Then safely use the argument:

```bash
RESULT=$(command "$VARIABLE")
```

A complete example:

```bash
#!/bin/bash

FILE_PATH="$1"

if [ -z "$FILE_PATH" ]; then
    echo "Usage: $0 FILE"
    exit 1
fi

if [ ! -f "$FILE_PATH" ]; then
    echo "Error: '$FILE_PATH' is not a regular file."
    exit 2
fi

NUMBER_OF_LINES=$(wc -l < "$FILE_PATH")

echo "There are $NUMBER_OF_LINES lines in $FILE_PATH."
```
