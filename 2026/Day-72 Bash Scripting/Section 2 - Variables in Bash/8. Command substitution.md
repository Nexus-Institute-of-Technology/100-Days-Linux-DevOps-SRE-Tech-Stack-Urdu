# 📖 Background

Command substitution is one of the most useful features in Bash.

It allows you to:

> Run a command and save its output inside a variable.

This is used frequently by:

- Linux administrators
- DevOps engineers
- System engineers
- SRE teams
- Cloud engineers
- Automation engineers

---

# What Is Command Substitution?

Suppose you run:

```bash
date
```

Example output:

```text
Fri Jul 17 10:30:15 AM CDT 2026
```

You can store this output inside a variable:

```bash
TODAY=$(date)
```

Now the variable `TODAY` contains the result of the `date` command.

Display it:

```bash
echo "$TODAY"
```

---

# Command Substitution Flow

```text
Command Runs
    │
    ▼
date
    │
    ▼
Output Is Captured
    │
    ▼
Fri Jul 17 10:30:15 AM CDT 2026
    │
    ▼
Stored in Variable
    │
    ▼
TODAY
```

---

# Modern Syntax

The recommended syntax is:

```bash
variable=$(command)
```

Example:

```bash
TODAY=$(date)
```

This is the modern and preferred method.

---

# Older Syntax

The older syntax uses backticks:

```bash
variable=`command`
```

Example:

```bash
TODAY=`date`
```

Both commands work, but the modern syntax is easier to read.

---

# Why Is `$(command)` Preferred?

The modern syntax:

```bash
$(command)
```

is preferred because it:

- Is easier to read.
- Is easier to identify in long scripts.
- Supports nested command substitution.
- Is easier to maintain.
- Is less confusing than backticks.

---

# Comparison

| Syntax | Status | Recommended |
|---|---|---|
| `$(command)` | Modern | Yes |
| `` `command` `` | Older | No, except when reading old scripts |

Correct:


Without quotes:


Bash may collapse multiple spaces and lines.

For multi-line content, use:


# LAB 11 – Understand the No-Space Rule

Correct:

```bash
TODAY=$(date)
```

Incorrect:

```bash
TODAY = $(date)
```

The incorrect command may produce an error such as:

```text
TODAY: command not found
```

---

# Why?

Bash variable assignment does not allow spaces around `=`.

Correct:

```bash
name=Ahmed
```

Incorrect:

```bash
name = Ahmed
```

---

# Bash Assignment Rule

```text
Variable Name
      │
      ▼
   TODAY
      │
      ▼
No Space
      │
      ▼
      =
      │
      ▼
No Space
      │
      ▼
   $(date)
```

Correct:

```bash
TODAY=$(date)
```

# LAB 12 – Create a System Information Script

Create:

```bash
nano system-report.sh
```

Add:

```bash
#!/bin/bash

# Script Name: system-report.sh
# Purpose: Demonstrate command substitution.

CURRENT_USER=$(whoami)
HOST=$(hostname)
KERNEL_VERSION=$(uname -r)
CURRENT_DIR=$(pwd)
CURRENT_DATE=$(date)

echo "================================="
echo "User: $CURRENT_USER"
echo "Hostname: $HOST"
echo "Operating System: $OS_NAME"
echo "Kernel Version: $KERNEL_VERSION"
echo "CPU Cores: $CPU_CORES"
echo "Current Directory: $CURRENT_DIR"
echo "System Uptime: $UPTIME_INFO"
echo "Date: $CURRENT_DATE"
echo "================================="
```

Save and exit.



```bash

```

This is useful for short commands.

---

# Variable Method vs Direct Method

## Variable Method

```bash
USER_NAME=$(whoami)
echo "Current User: $USER_NAME"
```

## Direct Method

```bash
echo "Current User: $(whoami)"
```

Both methods work.

Use variables when:

- The value is reused.
- The command is long.
- The script needs better readability.

# LAB 14 – Nested Command Substitution

Nested command substitution means placing one command substitution inside another.

Example:

```bash
FILE_COUNT=$(find "$(pwd)" -maxdepth 1 -type f | wc -l)
```

Display:

```bash
echo "Files in the current directory: $FILE_COUNT"
```

Here:

```bash
$(pwd)
```

runs first.

Then its output is used by:

```bash
find
```

This is one reason why `$(command)` is preferred over backticks.

---

# Nested Command Flow

```text
$(pwd)
   │
   ▼
/home/student/scripts
   │
   ▼
find /home/student/scripts ...
   │
   ▼
wc -l
   │
   ▼
Result Stored in FILE_COUNT
```

# 🔧 Troubleshooting

## Problem 1 – `command not found`

Incorrect:

```bash
TODAY = $(date)
```

Correct:

```bash
TODAY=$(date)
```

---

## Problem 2 – Variable Displays Nothing

Check whether the command produced output:

```bash
date
```

Then recreate the variable:

```bash
TODAY=$(date)
```

Display it:

```bash
echo "$TODAY"
```

---

## Problem 3 – Multi-Line Output Appears on One Line

Incorrect:

```bash
echo $YEAR_CALENDAR
```

Better:

```bash
echo "$YEAR_CALENDAR"
```

Best for preserving lines:

```bash
printf '%s\n' "$YEAR_CALENDAR"
```

---

## Problem 4 – Backticks Become Confusing

Avoid:

```bash
RESULT=`command1 `command2``
```

Use:

```bash
RESULT=$(command1 "$(command2)")
```

---

## Problem 5 – Command Output Includes Errors

Redirect errors:

```bash
RESULT=$(find /root -type f 2>/dev/null)
```

The error stream is sent to:

```text
/dev/null
```

---

## Problem 6 – Command Substitution Removes Trailing Newlines

Bash command substitution removes trailing newline characters from command output.

This is normal behavior.

For most administrative scripts, this is not a problem.

# 📖 Key Takeaways

- Command substitution captures command output.
- The recommended syntax is `$(command)`.
- Backticks are an older alternative.
- Modern syntax supports nested command substitution.
- Variable assignments cannot contain spaces around `=`.
- Command substitution can be used directly inside `echo`.
- It is useful for dynamic reports, backups, filenames, and monitoring scripts.
- Quoting variables protects spaces and multi-word values.
- Command substitution is widely used in Linux administration and DevOps automation.

# 💡 Remember

> **Command substitution turns command output into reusable data.**

```text
Linux Command
      │
      ▼
Command Output
      │
      ▼
$(command)
      │
      ▼
Stored in Variable
      │
      ▼
Used Elsewhere in Script
```

> **Golden Rule:**

```bash
VARIABLE=$(command)
```

Use the modern `$(command)` form whenever you need to capture and reuse the output of a Linux command.
